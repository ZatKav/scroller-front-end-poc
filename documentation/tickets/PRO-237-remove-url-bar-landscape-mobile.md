# PRO-237: Remove the URL bar on mobile landscape (PWA install)

## Summary
On mobile the browser URL bar eats vertical space, which is most painful in
landscape. There is no web API to remove the address bar on demand in a normal
browser tab — the Fullscreen API needs a user gesture and is unsupported for
elements on iPhone Safari (PRO-235 rejected it for exactly this reason). The
only reliable, cross-platform way to launch with no URL bar is installing the app
as a PWA. This change makes the scroller installable: it adds a web app manifest
with `display: "standalone"`, the iOS Apple-web-app meta tags, `viewport-fit:
cover`, safe-area-aware padding, and placeholder icons. Once the app is added to
the home screen and opened from its icon, it runs chrome-free (no URL bar) in
landscape and portrait on iOS and Android. Plain in-browser visits are
unchanged and keep the PRO-235 `dvh` sizing fallback.

## Changes
- `src/app/manifest.ts` (new):
  - `MetadataRoute.Manifest` with `display: "standalone"`, `name`/`short_name`,
    `background_color`/`theme_color`, and 192/512 + maskable icons.
  - `start_url`, `scope`, and every icon `src` are prefixed via `appPath()` from
    `src/lib/base-path.ts`, because Next prefixes the manifest *route* and the
    injected `<link rel="manifest">` with `NEXT_PUBLIC_BASE_PATH` but NOT the
    fields inside the manifest body. A wrong `start_url` makes the installed app
    launch to a 404 under the `/scroller` base path.
- `src/app/layout.tsx`:
  - Added `appleWebApp: { capable: true, statusBarStyle: "black-translucent",
    title: "Scroller" }` and an `apple-touch-icon` (base-path-prefixed via
    `appPath()`, since metadata URLs are not auto-prefixed).
  - Added `other: { "apple-mobile-web-app-capable": "yes" }`. Next 15 renders
    `appleWebApp.capable` as the standardised `<meta name="mobile-web-app-capable">`;
    iOS < 16.4 only honours the legacy apple-prefixed tag for home-screen
    standalone, so both are now emitted (iOS 16.4+ is covered by the manifest's
    `display: standalone`).
  - Added a Next 15 `viewport` export: `themeColor: "#4f46e5"` (matches the
    manifest) and `viewportFit: "cover"` so the standalone app fills the screen.
- `src/app/(protected)/page.tsx`:
  - `<main>` padding changed from `px-2 py-4 mobile-landscape:p-0` to
    safe-area-aware padding: `p{t,r,b,l}-[max(<base>,env(safe-area-inset-*))]`
    with `mobile-landscape:p{t,r,b,l}-[env(safe-area-inset-*)]`. With
    `viewport-fit: cover`, this keeps content (and the landscape image) clear of
    the notch/home indicator while preserving the previous look where insets are
    0 (desktop and non-notched devices).
- `public/icons/` (new): `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`,
  `apple-touch-icon.png`. Placeholder icons (solid indigo with a centred disc)
  generated by a dependency-free script; intended to be replaced with real brand
  assets later.
- `src/app/manifest.test.ts` (new): asserts `display: "standalone"`, the icon set
  incl. a maskable icon, and base-path prefixing of `start_url`/`scope`/icon
  `src` (root vs `/scroller`), mirroring the `resetModules` pattern in
  `base-path.test.ts`.
- `src/app/layout.test.tsx` (new): asserts the Apple web-app metadata, the legacy
  `apple-mobile-web-app-capable` tag via `other`, the apple-touch-icon, and
  `viewport.viewportFit === "cover"` / `themeColor`.

## Tests
- Ran: `make test-dashboard-unit` (jest) in `scroller-front-end-poc`.
- Result: pass — 106/106 tests across 12 suites (+7: 4 manifest, 3 layout). The
  existing PRO-235 "no Fullscreen API call" test stays green (the Fullscreen API
  is still not used; this ticket uses the manifest route instead).
- Also ran `npm run build` (Next 15 production build incl. type-checking): pass.
  Verified:
  - The built manifest (`/manifest.webmanifest`) is served with
    `content-type: application/manifest+json` and body `display: "standalone"`
    plus the three icons.
  - The prerendered `<head>` contains `<link rel="manifest">`, both
    `apple-mobile-web-app-capable` and `mobile-web-app-capable`,
    `apple-mobile-web-app-status-bar-style=black-translucent`, the
    `apple-touch-icon`, `theme-color=#4f46e5`, and `viewport ... viewport-fit=cover`.
  - The built CSS contains `env(safe-area-inset-*)`, `70dvh`/`100dvh`, and the
    `(orientation:landscape) and (max-height:600px)` media query.
- E2E (`make test-dashboard-e2e`, Playwright): NOT run here. The suite logs in
  and renders real stack-rank images, requiring the
  scroller-customer-interactions-db backend (not listening) plus credentials.
  PWA standalone / "no URL bar" cannot be asserted in headless Playwright anyway
  — it is verified by manual device QA (see Open questions).

## Open questions
- Manual device QA pending: confirm on a real iPhone (Safari → Share → Add to
  Home Screen) and Android (Chrome → Install) that launching from the icon shows
  no URL bar in landscape. Automated coverage stops at the manifest/meta/CSS
  build output.
- Placeholder icons should be swapped for real brand assets before any wider
  rollout.
- iOS ignores `display: "fullscreen"` (the status bar stays); `standalone` still
  removes the URL bar, which satisfies this ticket. First-time/uninstalled
  browser visitors still see the URL bar on iPhone — unavoidable; the PRO-235
  `dvh` fallback covers them.
- The Android-only Fullscreen-API "tap to go fullscreen" remains deferred to a
  separate follow-up ticket (out of scope here; it reverses the PRO-235 decision
  and is a no-op on iPhone).
